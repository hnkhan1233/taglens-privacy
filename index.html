TagLens — Privacy Policy

Last updated: 1 September 2026

TagLens is a developer diagnostic tool. It records the analytics activity of a web page you are visiting so you can see what your tracking did and did not send. This policy describes exactly what it handles and where that data goes.

The short version

TagLens does not have a server. Nothing it records is transmitted anywhere. There is no account, no login, no telemetry, no analytics on the extension itself, and no third party receives any of it. Everything the extension captures stays in your own browser's storage on your own machine.

What runs on every page

TagLens is a diagnostic tool, so a small amount of it has to be in place before you decide to record — otherwise pressing record would always miss the beginning of the page, which is the part being diagnosed. On every page you open, in every frame, whether or not you are recording, TagLens:

  • Watches dataLayer in the page so that a push made in the first milliseconds of a page load is not lost.
  • Sets one attribute, data-tag-assistant-prod-present, on the page's root element. This switches on a reporting channel that Google's own tag already carries and that Google's Tag Assistant uses. It makes the tag write down, in the page, each event it sends, which is what lets TagLens tell apart events that leave together in a single batched request. The attribute has to be in place before Google's tag starts, and Google's tag reads it exactly once, so it cannot be switched on only when you press record.
    • It does not change what the site sends. This was measured across 138 runs against Google's own tag: the requests, their parameters, their values, the cookies and the headers are identical with the attribute and without it.
    • What it does do is leave a record of that page's recent Google hits inside the page itself, where other scripts on that same site could read it. If you would rather that did not happen on a particular site, do not open that site with TagLens installed.
  • Asks the extension whether this tab is being recorded. Chrome attaches the page's address to that question as sender information. TagLens does not read it, but the browser makes it available, so the extension is capable of knowing the address of pages you open. The page's origin — the site name, not the full address — is also held in session memory for the tab, and is gone when the browser closes.

Apart from those, nothing about the page or about you leaves a tab you have not recorded. Two things are worth stating precisely, because "not recording" is not quite the same as "never recorded":

  • Recording is armed per page. A page you were recording keeps sending until you leave it, even after you press stop — the extension throws that away, and nothing from it is saved. It works this way because Google's tag numbers its own records per page, and breaking that numbering half way through makes TagLens distrust the whole page's evidence.
  • A new page opened after you stop sends nothing at all.

What TagLens records

While you are recording, and only on the tab you are recording, TagLens captures:

  • dataLayer pushes made by the page, including their contents.
  • Analytics requests the page sends — the URL, the decoded payload (event name and parameters), and a summary of the request headers.
  • The page's URL and title, so that captured events can be attributed to the page that produced them.
  • Your own settings and saved comparisons.

Because analytics payloads are the subject of the tool, a recording will contain whatever the site under test chose to put into them. On some sites that can include identifiers such as a user or account ID. TagLens surfaces this to you — that is frequently the defect being looked for — but it does not extract, separate, or transmit it.

Where it is stored

In chrome.storage.local and chrome.storage.session, which are areas of your own browser profile on your own device. The unlimitedStorage permission is requested so that a long recording is not silently truncated.

A recorded session is a draft until you press save this session. A draft is written to disk as it goes — so that closing your browser or Chrome suspending the extension cannot lose it mid-session — but it is not kept: it survives while a TagLens panel is open and is discarded when you close the last TagLens view.

A session you save is kept until you delete it or remove the extension. Recordings made before saving existed are kept for 30 days. Recordings a saved journey was cut from, and journeys used as a comparison baseline, are kept for as long as the thing that refers to them. At most 100 recordings are held at once; past that the oldest go first, and a saved recording is never one of them.

Uninstalling the extension removes them with it. TagLens has no ability to recover a recording once deleted, because it never held a copy.

Network activity

TagLens makes exactly one outbound network request in its entire codebase.

While you are recording, when it detects that the page has loaded a Google Tag Manager container, it performs a single GET for that same container URL — the identical URL the page itself has already requested — in order to read the container's public definition and determine which tags should have fired. Depending on the site, that URL is either on googletagmanager.com or on the site's own server-side Tag Manager domain. No data is sent with that request and no cookies or credentials are attached to it. On a tab you are not recording, this request is not made at all.

There is no other fetch, no XMLHttpRequest, no sendBeacon and no WebSocket anywhere in the extension.

What TagLens never does

  • It never sends your recordings, browsing history, or any captured payload off your device.
  • Limited Use. TagLens's use of information received from Google APIs, and of any data it handles, adheres to the Chrome Web Store User Data Policy, including the Limited Use requirements. It transfers that data nowhere, uses it for no purpose other than showing you the diagnosis you asked for, sells it to nobody, and no human ever reads it, because it never leaves your machine.
  • It never sells or shares data, because it never receives any.
  • It never blocks, redirects, or modifies the requests it observes — it only reads them.
  • It contains no eval, no new Function, and no remotely-loaded code. All code that runs is the code reviewed and shipped in the package.

The debugger permission

The debugger permission is granted when you install TagLens, and Chrome shows it to you at that moment. It cannot be made optional: Chrome refuses to accept debugger in an extension's optional_permissions and silently drops it, which is why an earlier version of TagLens that tried to ask for it only on demand had a replay button that could never work.

It is used for one thing: re-driving a recorded journey when you press replay. TagLens opens a new window of its own for the replay and attaches the debugger only to the tab inside it, for the length of that run, detaching when the run ends or is stopped. It is never attached to a tab you are browsing in, and it is not used at all while you are recording or reading a recording.

While the debugger is attached, Chrome displays its own banner across the top of the tab saying TagLens is debugging it. If you would rather not grant it, the only way to decline is not to install the extension — but nothing is sent anywhere either way; see “What TagLens never does” above.
